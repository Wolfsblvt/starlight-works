## Interaction and visual evidence

Browser tests exercised category navigation independently from disclosure, multiple open groups, default and current-ancestor behavior, separate keyboard focus, Space/Enter activation, native link attributes and autogeneration, all five alert labels/types, authored titles, rich Markdown, MDX, native asides, ordinary/unknown quotations and consumer CSS variables.

Native disclosure accessibility is read from Chromium's actual accessibility tree. The node is a named, focusable `DisclosureTriangle`; its expanded state changes from false to true after keyboard activation, and its open-state controls reference points at the child panel. Playwright's ARIA-only snapshot omitted this native role, so no artificial production role or static expanded attribute was added just to make that snapshot pass. This is machine-accessibility evidence, not a human screen-reader session.

Desktop light/dark pages, mobile light/dark navigation and mobile light/dark article screenshots are retained. The author inspected representative generated desktop and narrow content/navigation images: the category label and disclosure remain separate, long labels wrap, the five meanings remain visibly distinct, and the alert body retains lists and code. The browser suite also measured the sidebar's width and target separation. Screenshot evidence concerns these exact states, not every possible label, document or consumer theme.
